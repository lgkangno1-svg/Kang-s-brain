# 상세페이지 자동화 전용 Codex 지침

## 목적
이 폴더의 최우선 목적은 사용자가 상품명, 상품 사진, 특징 몇 줄만 제공해도 아래 파이프라인을 끝까지 수행하는 것입니다.

1. 제공 정보와 사진을 분석한다.
2. `source/TED_상페-고객님_정보요청_원본.txt`의 의도와 `source/TED_상페_Q1-Q10_빈양식.txt`의 Q1~Q10 구조에 맞춰 답을 스스로 완성한다.
3. Q1~Q10을 `source/상세페이지_마스터_원문.txt`에 정확히 주입한다.
4. 마스터 지침에 따라 썸네일 2장 + 상세페이지 12장 = 총 14장의 카피/구도/이미지 프롬프트를 만든다.
5. 이미지 생성 API가 사용 가능하면 14장을 실제 생성한다.
6. 최종 검증 후 상세 12장을 세로로 이어붙인 `detail_full.png`까지 만든다.

사용자에게 Q1~Q10을 다시 질문하지 마세요. 사용자가 준 정보가 적더라도 합리적으로 보완해 진행하세요.

## 작업 시작 전
루트 저장소 `AGENTS.md`의 fresh-state preflight를 반드시 먼저 지킵니다. 다른 에이전트가 같은 프로젝트를 수정 중인지 확인하고 충돌이 없음을 확인한 뒤 작업합니다.

## 입력 처리
- 사용자가 Codex 대화에 직접 첨부한 상품 사진/파일을 우선 사용합니다.
- 또는 `inbox/<상품슬러그>/` 아래의 `상품정보.txt`, 이미지, 시험성적서, 포장 사진 등을 사용합니다.
- 상품명만 있고 설명이 적으면 카테고리 상식과 구매 심리로 **소프트한 설득 맥락**은 보완할 수 있습니다.
- 그러나 가격, 원산지, 중량/수량, 인증, 시험 결과, 수치, 수상, 배송 조건, 의학/건강 효능처럼 검증이 필요한 **하드 팩트는 절대 발명하지 마세요.**
- 하드 팩트가 없으면 Q 답변 안에서 “미제공”으로 처리하고, 최종 카피에는 단정적으로 쓰지 마세요.
- 식품은 질병 예방/치료, 영유아 안전성, 특정 건강 개선을 증빙 없이 단정하지 마세요.

## 제품별 산출물
항상 `runs/YYYYMMDD-HHMM-<상품슬러그>/` 폴더를 새로 만들고 다음을 남깁니다.

- `00_input.md` : 사용자가 준 설명, 파일 목록, 사진에서 확인한 사실
- `01_q1_q10.json` : 기계 처리용 Q1~Q10 정답
- `01_Q1_Q10.txt` : 사람이 읽는 TED 양식 완성본
- `02_master_filled.txt` : Q1~Q10이 주입된 상세페이지 마스터 원문
- `03_strategy.md` : 골든서클 분석 + 메시지 포트폴리오 + 중복 방지 맵
- `04_image_jobs.json` : 14장 이미지 생성 작업 정의
- `05_final_copy.md` : 14장 최종 카피/프롬프트
- `images/` : 생성된 14장
- `detail_full.png` : 상세 12장 세로 결합본
- `VALIDATION.md` : 검증 결과

## 1단계 — Q1~Q10 자동 완성
`01_q1_q10.json`은 반드시 다음 키를 모두 포함합니다.

```json
{
  "product_name": "...",
  "q1": "...",
  "q2": "...",
  "q3": "...",
  "q4": "...",
  "q5": "...",
  "q6": "...",
  "q7": "...",
  "q8": "...",
  "q9": "...",
  "q10": "..."
}
```

Q1~Q10은 비워두지 않는 것이 목표입니다. 단, 하드 팩트가 없으면 사실을 만들지 말고 “가격 정보는 미제공이므로 가격 자체가 아닌 체감 가치 중심으로 포지셔닝”처럼 안전하게 완성합니다.

JSON을 만든 뒤 다음을 실행합니다.

```bash
python scripts/build_master.py runs/<RUN>/01_q1_q10.json
```

이 스크립트가 `01_Q1_Q10.txt`와 `02_master_filled.txt`를 자동 생성합니다.

## 2단계 — 14장 전략/카피/프롬프트
반드시 `02_master_filled.txt` 전체를 읽은 뒤 작업합니다.
마스터의 구조와 해상도를 변경하지 마세요.

필수 순서:
1. 골든 서클 분석
2. 메시지 포트폴리오 5~7개
3. 14장 중복 방지 메시지 맵
4. 14장 최종 카피/구도
5. 14개 image prompt

동일한 증거/키워드/메인 카피를 반복하지 마세요. 가장 강한 WHY는 전체 20~30%, 나머지는 신선도/맛/사용 경험/영양/가격 가치/배송·보관 등 적합한 축으로 분산합니다.

## 3단계 — `04_image_jobs.json`
정확히 아래 14개 ID를 사용합니다.

`thumb_1`, `thumb_2`, `image_1` ... `image_12`

각 객체:
```json
{
  "id": "thumb_1",
  "type": "thumbnail",
  "width": 1000,
  "height": 1000,
  "axis": "painpoint",
  "main_copy": "...",
  "sub_copy": "...",
  "points": ["...", "..."],
  "rendering": "...",
  "prompt": "...",
  "reference_images": ["inbox/<상품>/제품1.jpg"]
}
```

해상도 고정:
- thumb_1 1000x1000
- thumb_2 1000x1000
- image_1 860x1800
- image_2 860x1800
- image_3 860x1800
- image_4 860x2000
- image_5 860x2000
- image_6 860x2200
- image_7 860x2000
- image_8 860x1800
- image_9 860x1800
- image_10 860x1800
- image_11 860x2500
- image_12 860x1500

모든 `prompt`에는 다음 품질 체인을 자연스럽게 포함합니다:
`photorealistic, commercial photography, natural lighting, clean ecommerce design, highly detailed, 8k resolution`

상품 실물 사진이 있으면 제품 정체성/포장/라벨/형태를 가능한 한 유지하도록 프롬프트에 명시하고 `reference_images`에 연결합니다.

## 4단계 — 실제 이미지 생성
`OPENAI_API_KEY`가 존재하면 다음을 실행합니다.

```bash
python scripts/generate_images.py runs/<RUN>/04_image_jobs.json
```

- 기본 모델: `gpt-image-2`
- 기본 품질: `medium`
- 중간 실패 시 이미 생성된 파일을 건너뛰므로 재실행해 이어서 생성합니다.
- `--force`를 붙인 경우에만 기존 이미지를 다시 생성합니다.
- 참조 이미지가 지정된 작업은 이미지 편집 API를 사용합니다.
- API용 크기는 16px 배수로 자동 보정하고, 저장 시 마스터의 정확한 최종 크기로 리사이즈합니다.
- 상세 12장은 자동으로 `detail_full.png`로 이어붙입니다.

API 키가 없으면 이미지 단계만 건너뛰고, `04_image_jobs.json`과 `05_final_copy.md`까지 완성해 두세요. 추가 질문으로 작업을 멈추지 마세요.

## 5단계 — 검증
항상 아래를 실행합니다.

```bash
python scripts/validate_run.py runs/<RUN>
```

실제 이미지까지 생성했으면:
```bash
python scripts/validate_run.py runs/<RUN> --require-images
```

검증 실패 시 원인을 수정하고 다시 검사합니다.
